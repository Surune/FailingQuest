# 게임 흐름 구현 및 검증

## 구현

- 시작 → 동료 3명 선택 → 첫 퀘스트 → 지도 → 각 노드 → 지도 복귀.
- 전투에는 지원대원 1명을 더해 기존 4인 진형을 유지한다.
- 첫 퀘스트로 이동하는 버튼의 씬 이름을 `FirstQuestScene`으로 수정했다.
- 모든 지도 노드 이동에 공통 SceneLoader를 사용한다.
- 지도 진입 시 데이터와 지도를 하나의 체크포인트로 저장한다. 이어하기는 마지막 지도 시점을 복원한다. 노드 내부에서 종료하면 해당 노드에서 얻은 미확정 보상은 복원하지 않는다.
- 새 게임, 클리어, 전멸 시 체크포인트를 종료한다.
- 일반 전투는 기존 능력치/100골드, 엘리트는 체력 1.25배·속도 +1·피해 +1/150골드다. 보스 전투는 첫 적을 체력 2배·속도 +2·피해 +2의 군주로, 나머지 적을 정예로 구성하고 250골드를 지급한다. 기존 적 그래픽을 사용한다.
- 결과 화면에 탐험 장소, 전투 승리, 엘리트 격파, 후퇴, 라운드, 골드, 유물을 표시하고 다시 도전/홈 버튼을 제공한다.
- 이어하기와 원정 기록 UI는 저장된 프리팹을 사용한다. 런타임 UI 부트스트랩은 추가하지 않았다.

## 확인 결과

Unity 6000.3.15f1에서 확인했다.

- 스크립트 컴파일 오류 없음.
- 기존 13개 씬 진입 검사: 예외 없음, GameManager/DataManager 각각 1개.
- 기존 전투 회귀 검사 및 시드 전투 10회 통과.
- 67개 스킬 에셋의 참조, 대상 지정, 실행, 복사 및 복합 효과 검사 통과.
- `FlowValidation/FlowChecks.cs`: 시작 버튼, 첫 퀘스트 버튼, 체크포인트 복원, 일반/엘리트/보스 능력치와 보상, 중복 보상 방지, 승리 이동, 재도전 초기화, 후퇴 경로, 전멸 이동 등 22개 검사 통과.
- 흐름 검사의 승리/전멸은 결과 분기를 확인하기 위해 전투 상태를 지정한다. 전체 원정을 수동으로 플레이한 밸런스 검증은 아니다.
- 검증 전 UserData/Map/RunCheckpoint를 `Temp/FlowAudit/playerprefs.json`에 백업하고 검증 후 원래 저장 데이터를 복원했다.
- 시작 화면과 결과 화면을 게임 뷰에서 점검했다. 발견한 결과 버튼의 캐릭터 그림 겹침을 수정했다.
- 지도 노드 파괴 시 DOTween을 종료해 씬 이동 후 남는 애니메이션 경고를 제거했다. 수정 후 22개 흐름 검사를 재실행했다.
- TMP 공통 대체 글꼴에 Galmuri11을 연결해 기본 영문 글꼴을 사용하는 UI의 한글 누락을 보완했다.
- Windows 64비트 실행 파일 빌드 성공. 출력은 `Builds/Windows/FailingQuest.exe`다. 별도 실행 파일의 전체 수동 플레이와 장기 밸런스 검증은 남아 있다.

상세 로그: `Temp/SceneAudit/smoke.json`, `Temp/FlowAudit/flow.json`.
